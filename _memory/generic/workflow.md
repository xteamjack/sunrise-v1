# Workflow (generic)

1. Plan first for a non-trivial change; show the plan before editing.
2. Find the component type in solution/componentCatalog.md; build in its home.
3. Build the smallest working version of one component at a time.
4. Validate the component, then run the eval gate (/eval, once it exists).
5. Update _memory: registry.md when you add a component, and any shape or decision.
6. Commit with a clear message naming the module.

Never skip the gate once it exists (Module 9). Never leave _memory stale.
